## Правило за движение

Нова техническа задача може да се изпрати автоматично само след окончателен HANDOFF, край на изпълняващата сесия, стабилен PR head и независим преглед на реалния diff с **всички приложими acceptance тестове PASS върху същия SHA**. Green CI, PR body, междинен push или PASS от самия изпълнител не са достатъчни. При липсващо доказателство системата спира, записва причина и не изпраща.

## Ритъм на работа

Мониторът проверява общата GitHub опашка приблизително на 5 минути и остава тих при непроменено състояние. При завършен HANDOFF проверява exact SHA, реалния diff и тестовете в изолирано копие; записва verdict, доказателства и проблем в `coordination/REVIEWS/<Task-ID>.md`, след което обновява `ACTIVE.md` и дневника. При PASS подготвя следващата най-малка техническа задача с точен base SHA, scope, exclusions и acceptance tests. При CHANGES_REQUESTED допуска най-много един ограничен коригиращ цикъл. При BLOCKED не изпраща нищо.

Крум не се включва за рутинно копиране, тестове и технически решения в вече разрешения scope. Само той решава нови бизнес правила, security/access, production/NAS/Atlas, merge/deploy и destructive migration.

## Ограничение на автоматичното изпращане

Описанието и локалният проверяващ инструмент не са жив Claude транспорт. Claude Routines остават изключени. Не се ползва локален Claude CLI или платен API без изрично решение. Докато директната Claude Desktop Code Cloud сесия и правата ѝ не са потвърдени, статусът е PENDING/BLOCKED, а не привиден RUNNING. Никой файл от този прототип не разрешава самостоятелно dispatch.
