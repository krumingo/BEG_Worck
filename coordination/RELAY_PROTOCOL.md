# Протокол Codex ↔ Claude за BEG_Work

## Единна истина

`ACTIVE.md` е единственият указател за активна задача и Dispatch-State. `REVIEWS/<Task-ID>.md` съдържа независимия verdict и доказателствата. `WORK_PLAN.md` е човешкият график. `ACTIVITY_LOG.jsonl` е append-only журнал от момента на въвеждането му; по-стара история не се измисля. Във всеки запис се пазят UTC време, Task-ID, actor, event, branch, точен base/head SHA, източник/доказателство, result, problem_count и owner_required, когато са известни.

## Машина на състоянията

1. `PENDING`: готова ограничена задача с доказани prerequisites, точен base SHA, scope/exclusions и acceptance tests. Проверка за вече изпратена сесия и idempotency key.
2. `RUNNING`: само след потвърдено изпращане през редовна директна Claude Desktop Code Cloud сесия към правилното repo/branch и наблюдавано начало. Записват се URL/ID и SHA. Не се изпраща дубликат.
3. `AWAITING_REVIEW`: само след финален HANDOFF, край на сесията и стабилен PR head. Междинният push не е HANDOFF.
4. `PASS`: реалният diff и всички приложими acceptance тестове са независимо проверени в изолирано копие върху exact PR head; резултатите и командите са в REVIEW.
5. `CHANGES_REQUESTED`: конкретен дефект с възпроизводимо доказателство; най-много един ограничен коригиращ цикъл.
6. `BLOCKED`: липсващо доказателство, owner решение, несъвпадащ SHA, изчерпан коригиращ цикъл, недостъпен директен UI или нерешен сериозен дефект. Не се изпраща следваща задача.

## Абсолютен тестов gate

Нов Task-ID се допуска само ако предишният има `PASS`, review head = актуален PR head, финален HANDOFF/session-end, стабилен head и пълен набор приложими тестове: положителни, забранени/negative, tenant isolation, idempotency, rollback, regression и специфичните за задачата проверки. Всеки неприложим тест се отбелязва с причина; липсващ резултат спира прехода. След нов push предишният PASS за стария SHA не важи.

## Собственост и безопасност

Автоматично се възлагат само вече одобрени технически задачи. Нови бизнес правила, security/access, production/NAS/Atlas, merge/deploy и разрушителни миграции чакат Крум. Не се използват Claude Routines, невписан локален Claude CLI или платен API ключ. GitHub е общият журнал/опашка, не сам по себе си механизъм за стартиране на Claude.

Прототипният `tools/agent_relay.py` изчислява решение офлайн и няма мрежови операции, ключове или изпращане. Жив dispatch изисква отделно потвърден безопасен канал и права; до тогава `READY_TO_DISPATCH` е само препоръка, не извършено изпращане.
