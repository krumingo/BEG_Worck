## Bounded security finding

`backend/app/routes/media.py` exposes `GET /api/media/avatar/{filename}` with **no `get_current_user` dependency**. The new owner lookup checks that a row is a current profile photo in its own tenant, which correctly blocks arbitrary invoice photos, orphans and stale avatars; it does not authenticate the caller or bind the caller to that tenant. The committed HTTP-level `test_a_current_profile_photo_is_still_served_without_a_session` intentionally asserts `200` for both tenant A's and tenant B's current avatars in one unauthenticated client. Codex ran that test in the 434-pass focused selection. Thus a client without any session can retrieve the current photo of another tenant by its stored filename/URL. `Cache-Control: private` and an unguessable-looking filename do not establish FLOW-002 authorization before read.

Close this in the W0-06B file-access slice: require an authenticated, tenant-authorized fetch, or a short-lived tenant-scoped protected grant whose issuance enforces FLOW-002; adapt plain `<img src>` consumers accordingly. Add negative HTTP tests for unauthenticated and cross-tenant current-avatar requests, while retaining tests that invoice/other files cannot be served. Do not weaken the restriction to merely checking that the profile belongs to *some* tenant.
