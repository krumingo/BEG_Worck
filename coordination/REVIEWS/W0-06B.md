### Bounded C02 finding

`frontend/src/components/AuthImage.js` has a module-global `Map` keyed only by avatar path. A cache hit returns the previous object URL without consulting the current token/tenant. `frontend/src/contexts/AuthContext.js` logout clears local storage/state but does not clear this cache, and the normal SPA logout does not reload the page. Codex executed the actual `load` function from the C02 source in a Node VM: first tenant A returned `blob:TENANT_A`; after switching to tenant B, the same path returned `blob:TENANT_A`, with **one** API request total. This bypasses the server's newly enforced tenant check in the client and can expose an earlier tenant's avatar across a same-tab account switch. The claimed five-minute expiry also is not enforced by a timer: stale blob URLs are only revoked when the same path is loaded again.

Correct only this avatar path's protected client cache: bind cache entries to the authenticated principal/tenant or clear and revoke them on account/session change, never return a prior principal's blob to a new principal, and enforce the short lifetime. Add a frontend regression for same-tab tenant/account switch with identical avatar path, alongside positive same-tenant reuse and logout/expiry behavior. Preserve existing authenticated backend route and bounded C02 scope. Do not touch providers, onboarding, integrity, File models, unrelated routes, W0-07, merge or deploy. A new final exact-head HANDOFF and independent review are required. C02 CHANGES_REQUESTED is not FLOW-016 Gate PASS.

## Bounded security finding

`backend/app/routes/media.py` exposes `GET /api/media/avatar/{filename}` with **no `get_current_user` dependency**. The new owner lookup checks that a row is a current profile photo in its own tenant, which correctly blocks arbitrary invoice photos, orphans and stale avatars; it does not authenticate the caller or bind the caller to that tenant. The committed HTTP-level `test_a_current_profile_photo_is_still_served_without_a_session` intentionally asserts `200` for both tenant A's and tenant B's current avatars in one unauthenticated client. Codex ran that test in the 434-pass focused selection. Thus a client without any session can retrieve the current photo of another tenant by its stored filename/URL. `Cache-Control: private` and an unguessable-looking filename do not establish FLOW-002 authorization before read.

Close this in the W0-06B file-access slice: require an authenticated, tenant-authorized fetch, or a short-lived tenant-scoped protected grant whose issuance enforces FLOW-002; adapt plain `<img src>` consumers accordingly. Add negative HTTP tests for unauthenticated and cross-tenant current-avatar requests, while retaining tests that invoice/other files cannot be served. Do not weaken the restriction to merely checking that the profile belongs to *some* tenant.
