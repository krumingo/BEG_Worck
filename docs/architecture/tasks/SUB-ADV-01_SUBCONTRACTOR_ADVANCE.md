# SUB-ADV-01 — аванс към подизпълнител, приспадан от актовете
> ОДОБРЕНА от Крум (Р39, Р40, 07.11.2026). Стъпва на PR #69 (SEC-01, клон `claude/sec-01-money-write-permissions`) — нов клон от неговия head, draft PR към main, слива се след #69. Канон: FLOW-021 (подизпълнители: задължение/акт), FLOW-006 (единен Payment ledger), CLAUDE §2.5, §7 (без автоматично нетиране на вземания и задължения — приспадането е изрично действие по акт), §14. Codex: да.

## Какво
1. **Аванс:** нов вид запис по пакет на подизпълнител — сума, дата, причина; реалното плащане минава през `finance_payments` (FLOW-006), без втори регистър. Само Owner/Accountant (финансовите роли по Р14 — ако Admin трябва да изключи, следвай канона/каталога и опиши). Idempotency-Key (Р29), AuditEvent, без hard delete (сторно като PAY-01 за аванс — ако #70 още не е слят, 409 SOURCE_MODULE_REVERSAL_REQUIRED както FG-45).
2. **Приспадане:** при плащане/удостоверяване на следващ акт неприспаднатият аванс се приспада **изрично** (поле „приспаднат аванс“ по акта, видимо и записано, с AuditEvent), не тихо; остатъкът на аванса се следи по пакета.
3. **Таван (Р40):** по пакет: обикновените плащания ≤ удостоверено − вече платено; авансът не е обикновено плащане и не се брои като надплащане по FG-90, но общият паричен поток към пакета се вижда (аванс + плащания − приспаднато). Резервацията `committed_paid_total` да отчита аванса и приспадането правилно.
4. **Екран/API:** пакетът показва: удостоверено, платено, аванси, приспаднато, остатък на аванса. На български.
## Тестове
- аванс 1000 → плащане по акт 3000 с приспаднат аванс 1000 → платено 2000, остатък аванс 0; паралелни авански заявки с един ключ → 1; роли × 3 режима; обикновено плащане над удостовереното → 409 (непроменено).
