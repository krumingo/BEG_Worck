# LAB-02 — въвеждане и одобрение на изработено количество + акордна цена по СМР
> ОДОБРЕНА от Крум (Р33, 07.11.2026). Стъпва на PR #73 (LAB-01) — клон от `claude/lab-01-labor-cost`; LAB-01 и LAB-02 се сливат заедно. Канон: FLOW-028 (акорд = одобрено количество × акордна цена), FLOW-019, CLAUDE §7/§8, FLOW-043 D-02. Codex: да (заплати).

## Какво да се направи
1. **Акордна цена по СМР/пакет:** финансова роля (Owner/Admin/Accountant) задава `labor_pay_type` и `labor_piece_rate` на пакета/СМР (с версия и AuditEvent; промяна не пипа вече одобрени количества).
2. **Въвеждане на количество:** работникът/бригадирът попълва изработеното количество (м2/бр/м и т.н., мярката от СМР) на ред от дневния отчет — само на свой отчет (Р36 за поправки).
3. **Одобрение:** одобряващ (SiteManager на обекта, Admin, Owner; ≠ работника) одобрява/коригира количеството → `labor_quantity_approvals` (вързано за report id + version + entry id, FG-72). Поправка на отчета анулира одобрението.
4. **Престой (DOWNTIME):** одобряващият класифицира ред като престой с причина (връща възможността, отнета в LAB-01-C).
5. **Екрани:** в дневния отчет — поле „количество“; за одобряващия — списък „за одобрение“ с количество, мярка, СМР; за финанси — акордна цена по СМР. На български. Мобилен изглед 390 px.
6. Права, Idempotency-Key (Р29), AuditEvent за всеки запис; без hard delete.
## Тестове
- акорд: 120 м2 одобрени × 5 → 600 в Pay Run и в „изхарчено“; работник не може да одобри своето; промяна на отчета → одобрението отпада; DOWNTIME отделен ред.
