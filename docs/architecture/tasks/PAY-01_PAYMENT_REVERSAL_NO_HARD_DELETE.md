# PAY-01 — плащанията не се трият, а се сторнират (FG-34)
> ОДОБРЕНА от Крум (Р23, 06.11.2026). Нов PR от `main`. Codex: да (пари).
> Канон: CLAUDE.md §2.9 (няма hard delete на финансови записи), §7 (reversal/correction вместо редакция), FLOW-006 §Корекции, FLOW-043 D-03, D-08.

## Проблем (FLOW Guard FG-34 @ main 07da9ab)
- `backend/app/routes/finance.py` ~1435: `DELETE /finance/payments/{id}` → `finance_payments.delete_one`.
- ~1218/1223: премахване на разпределение по фактура → `payment_allocations.delete_one` и понякога `finance_payments.delete_one`.
- Няма canonical AuditEvent, записът изчезва.

## Какво да се направи
1. Плащане: DELETE вече не трие. Създава **сторно** (обратен запис в `finance_payments` със връзка към оригинала, статус на оригинала `reversed`), с причина (задължителна), кой и кога. Повторно сторно → 409. Идемпотентност (idempotency key).
2. Разпределение по фактура: отменя се със статус/обратен ред, не с delete; салдата на фактурата и плащането се преизчисляват от неотменените редове.
3. Всички справки, които четат `finance_payments`/`payment_allocations` (вкл. dashboard, cash, P&L, обща helper функция от #55), игнорират отменените/сторнираните двойки → нетно 0. Изброи ги в HANDOFF.
4. AuditEvent по общия envelope (W0-04 е известен дълг за паралелни записи — не го поправяй тук, само го ползвай).
5. Права: само финансовите роли (Owner/Admin/Accountant), по същия `require_money_write` като SEC-01 (#69). Ако #69 още не е слят, ползвай текущата проверка и опиши в HANDOFF как ще се слее.
6. `invoices.delete_one` (~1072) и `financial_accounts.delete_one` (~604): провери. Разрешено само за чернова/неизползван запис; използван → 409. Не добавяй нова функционалност отвъд това.
7. Без миграция на стари данни, освен ако е нужна за нов статус — тогава idempotent и описана.

## Тестове (real Mongo, падат на main)
- DELETE плащане → оригиналът остава, има сторно, AuditEvent, справките показват 0; второ DELETE → 409.
- Отмяна на разпределение → нищо изтрито, салдата верни.
- Viewer/SiteManager → 403, нищо записано; трите режима.
- Използвана фактура/сметка → 409.
- R0/W0 baseline без нови падания; A2C/A1 guard 0.

`HANDOFF PAY-01` с head, тестове, засегнати справки, rollback.
