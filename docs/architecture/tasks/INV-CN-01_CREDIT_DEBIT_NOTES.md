## 1. Статуси и заключване (Р49.1–2)
- Изходяща фактура: `чернова` → `издадена` (получава номер; заключена) → `изпратена` → (`частично платена`/`платена`) ; `анулирана` (само от `издадена`, неизпратена, неплатена, не в ДДС дневник; с причина; номерът остава).
- Всяка промяна по сума/редове/ДДС/контрагент на издадена фактура → 409 `INVOICE_LOCKED`; само чернова е редактируема. Без hard delete на фактура с номер (и анулирана).
- Анулиране след изпращане/плащане → 409 `USE_CREDIT_NOTE`.
- Докажи на main: днес издадена/платена фактура се редактира/изтрива (FG от t28) — червен тест.

## 2. Кредитно / дебитно известие (Р49.2–5, 7)
- Отделен immutable документ (FLOW-025 L144): `kind` credit|debit, `direction` outgoing|incoming, **номер от общата поредица с фактурите** (атомарен брояч per tenant, уникален индекс), `original_invoice_id` задължително, редове с референция към редовете на оригинала (количество или сума), net/VAT/gross отделно, причина, `file_id` (File Registry), AuditEvent.
- Кредитно: Σ кредитирано по ред ≤ фактурираното по реда минус вече кредитирано (атомарно, конкурентно безопасно) → иначе 409 `CREDIT_EXCEEDS_INVOICED`.
- Дебитно към клиент: изисква основание — одобрен акт/анекс (ref) → иначе 422 `DEBIT_NOTE_BASIS_REQUIRED`; ако моделът на анекс липсва — само акт + дълг.
- Изходящо известие: Accountant създава (чернова), **Owner одобрява** (различен човек → иначе 409 `SAME_PERSON_APPROVAL`); едва одобреното получава номер. Approval сочи exact version (§8). AI само чернова (FLOW-006 L92).
- Ефект: намалява/увеличава отвореното вземане/задължение; **не** променя договорната стойност. P&L: в **периода на известието**, по обекта/СМР на оригиналната фактура (Р49.7); затворен период не се пипа.
- Фактура от акт (Р49.5): кредитното намалява „фактурирано“ по акта (частта отново може да се фактурира); количеството в акта не се пипа (корекцията на акта е отделна — не е в обхвата, дълг към t24). Твърд таван: Σ фактурирано по акт (минус кредитирано) ≤ стойността на акта → 409 `ACT_OVER_INVOICED` (конкурентно безопасно).

## 3. Платена фактура (Р49.6)
- Кредитно по платена → салдо (`credit_balance`) към контрагента по договора. Без автоматично нетиране. Действия на Accountant: (а) връщане = плащане през FLOW-006 (единния Payment ledger, с Idempotency-Key); (б) прихващане = изричен запис с източниците, само в същия договор (иначе 409 `OFFSET_ACROSS_CONTRACTS`), AuditEvent; над праг → второ одобрение (праг конфигурируем per tenant, по подразбиране 5 000 €; запиши като дълг ако Approval runtime липсва).

## 4. Входящо кредитно известие от доставчик (Р47 + Р49.8)
- Регистрация от Accountant, свързване с `expected_credit_notes` (от #82; ако #82 не е в main — направи регистрацията и съвпадението независимо, с ясно място за свързване, и запиши дълг „whichever merges second“).
- Съвпадение до 0.01 → очакваното е изпълнено, лимитът на плащане се преизчислява (нетно получено − кредит), DQ се затваря. Разлика → лимитът остава, DQ „разлика в кредитно известие“. Срок 14 дни от сторното → ескалация към Owner (изчислено при четене, без запис в GET).
- Дубликат (същият номер от същия доставчик) → 409.

## Общо (§14)
Права по SEC-01/PM-01 (финансово действие; само Owner/Accountant/Admin пишат; Owner одобрява). Idempotency-Key задължителен (Р29). Транзакция + canonical AuditEvent (record_event със session). Режими off/shadow/enforce. Регенерирай PM-01 САМО с harness и реален Mongo (0 skipped, `-rs`). UI: минимален — статус, „Анулирай“/„Кредитно известие“, грешките на български.
