# SEC-01-C03 — сума и повторна заявка при плащания (одит #69)
> ОДОБРЕНА — прилагане на канона, без ново бизнес решение: CLAUDE.md §14 (validation/DQ + idempotency key за всеки consequential write), FLOW-006, Р14, Р16. PR #69 @ 471eaaa. Codex: да.

## Проблеми (одит @ f33b2ba, БЛОКИРАЩИ)
1. `amount` = `"nan"`, `"inf"`, `"1e309"` минава проверката `<= 0` → записва се `finance_payments` Outflow с NaN, после 500.
2. Еднакъв POST два пъти → 2 изходящи плащания (дълг D1). Обикновен retry = двойно плащане.

## Какво да се направи
1. Всички записи на пари, пипнати в SEC-01/C01/C02 (вкл. subcontractor payments, cash/bonus/overhead, труд/отпадък суми): сумата трябва да е крайно число > 0 (и разумен горен лимит, ако има в канона/модела; ако няма — само крайно), иначе 422 и **нищо записано**. Валидацията е преди всеки запис, без частични записи.
2. Idempotency key за subcontractor payment и останалите money POST-ове от #69: заглавие `Idempotency-Key` (или съществуващия общ механизъм в кода, ако има — потърси го и го ползвай). Повтор със същия ключ и същото тяло → същият отговор, без нов ред; същия ключ с различно тяло → 409. Без ключ — приеми, но опиши в HANDOFF (не чупи сегашните клиенти); фронтендът на тези форми да праща ключ.
3. SEC-R1: одитът е проверил f33b2ba; потвърди, че 471eaaa го затваря, и добави теста в общия матричен тест, ако липсва.
