# ACT-01 — Клиентски акт: цена и количество от офертата, остатък, без двойно актуване

> Дата: 07.11.2026 · Източник: FLOW Guard pass 11, FG-106 (high, SUSPECTED) · Wave 1 Commercial Core
> Канон: FLOW-004 (BUSINESS LOCK), FLOW-006, FLOW-043, CLAUDE.md §2, §7, §8, §14, §15. Решения: Р29 (пари без Idempotency-Key → 428).
> Клон: нов от main `0f870c3`, `claude/act-01-client-act-from-offer`. Draft PR към main. Без merge/deploy.

## Проблем (main @ 0f870c3, `backend/app/routes/revenue_expense.py:65–160`)
- `POST /client-acts` и `PUT /client-acts/{id}` приемат `unit_price`, `executed_qty`, `contracted_qty` от заявката; `offer_line_id` е по избор.
- Няма проверка на остатъка, няма защита от двойно актуване (последователно и конкурентно).
- Номерът на акта се смята от последния запис (`get_next_act_number`) — конкурентно дава еднакви номера.
- Няма Idempotency-Key, AuditEvent, tenant/permission проверки по канона.
Първо ДОКАЖИ всяко от горните с тест на реален Mongo (червен на main), после поправи.

## Какво да се направи (по FLOW-004)
1. **Ред на акт = връзка към офертен ред** на одобрена оферта/договорен обхват на СЪЩИЯ обект и tenant (сървърно разрешено, не от body). Ред без връзка → 422, освен ако е свързан с договорно основание за допълнително СМР (допълнителна оферта / анекс / одобрен Change Request), ако такъв модел съществува; ако не съществува → 422 и запиши дълг.
2. **Цена:** единичната цена идва от офертния ред (или от действащ анекс, ако има модел). Подадена различна цена → 422 `UNIT_PRICE_MISMATCH` (FLOW-004: „различна единична цена в акт без анекс“ е забранено). `contracted_qty` също от офертата, не от body.
3. **Остатък:** fixed_price — Σ актувано по офертния ред (всички неанулирани актове, вкл. чернови) + новото ≤ офертното количество, иначе 409 `ACT_EXCEEDS_REMAINING`. Ако в модела има remeasurement режим — таванът е одобреното измерено количество; ако няма режим на договора, приеми fixed_price и запиши дълг (не измисляй режим).
4. **Без двойно актуване под конкуренция:** атомарна резервация по офертен ред (условен `$inc` с таван или заключване по ред) в същата транзакция като записа на акта. 6 конкурентни акта ×10 → само разрешеното количество минава.
5. **Номер на акт:** атомарен брояч per tenant (не „последният + 1“); уникален индекс.
6. **Редакция:** само Draft; същите проверки при PUT (резервацията се коригира атомарно с разликата). Одобрен акт не се редактира тихо → корекция/сторно с причина (ако моделът за одобрение съществува; иначе запиши дълг). Без hard delete.
7. **Р29 / §14:** Idempotency-Key задължителен на POST/PUT (428 без ключ; replay → същият отговор; същият ключ, различно тяло → 409). Ползвай общия W0-04 `begin_idempotent` (както #69/#70) — същия механизъм, не нов.
8. **Права и tenant:** провери кой има право на `require_m2` днес; правата за създаване/редакция на клиентски акт по PM-01 матрицата и SEC-01 каталога (финансово действие). Не разширявай права. Регенерирай PM-01 САМО с harness, с `W0_03_REAL_MONGO_URL` зададен (да не се skip-не).
9. **AuditEvent:** един canonical event за create / update / correction.
10. **Четци:** отговорите показват договорено / актувано / остатък по ред (FLOW-004 „Какво трябва да вижда Крум“). Не-финансови роли — по SEC-02 правилата (без пари, ако нямат право).

## Допълнение A (07.11) — D1 (две приети версии на оферта) по канона
Канон: FLOW-003 „Версии“ — промяната създава НОВА ВЕРСИЯ на същата оферта, старата остава видима, но не може да се одобрява след публикуване на нова; „при ново възлагане се създава ДОПЪЛНИТЕЛНА оферта“. FLOW-005: дублирането се контролира на ниво оферта, версия и офертен ред.
- Версии на една оферта = един обхват. Актува се само по последната приета версия; акт по ред от заменена версия → 409 `OFFER_VERSION_SUPERSEDED`.
- Таванът е по реда на действащата версия, а вече актуваното по съответния ред от предишни версии се брои в него (родословие ред→ред). Ако моделът няма връзка ред-към-ред между версиите — съпоставяй по стабилен ключ, ако има такъв; иначе откажи актуване по оферта с > 1 приета версия с 409 `OFFER_VERSION_LINEAGE_UNKNOWN` и запиши дълг (не сумирай два тавана).
- Допълнителна оферта (отделна оферта, ново възлагане) = отделен таван.
- Тестове: v1 приета, актувано 6/10; v2 приета (10→12) → по v2 остават 6; по v1 → 409; допълнителна оферта → собствен таван.
