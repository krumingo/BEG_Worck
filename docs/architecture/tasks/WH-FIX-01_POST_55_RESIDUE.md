## Допълнение A2 (08.11) — FG-155 по канона, ЗАМЕНЯ Допълнение A
Канон, изцяло прочетен от FLOW Guard (oracle Q001, claude/flow-guard @ 163100b, docs/flow-guard/oracle/Q001_partial_invoice_line_allocation.md):
- FLOW-020 L73 „Сборът на разпределенията трябва да е равен на фактурираното количество.“; L200 забранява „фактурен ред без дестинация да стане окончателен“; FLOW-009 L84 „Остатъкът не изчезва; системата изисква валидна дестинация.“
- Частичното разпределение е само междинен статус „чака разпределение“ (FLOW-033 L101); не участва в официалните резултати (FLOW-033 L106; FLOW-008 L142).
- Дестинации (FLOW-020 L54–60): обект/подобект/СМР, склад, служител, машина/превозно средство, фирмен overhead scope — само изрично избрани, без мълчалив default (FLOW-024 L115, L205).
Направи:
1. Редът/фактурата е „окончателно разпределен(а)“ само при сбор = фактурираното количество; иначе статус „чака разпределение“. require_full_allocation по подразбиране = True за окончателния статус (FG-155).
2. Неразпределеният остатък не влиза в P&L на обект, в наличност, нито във фирмения резултат; никакъв автоматичен default.
3. Един дедублициран DQ issue „фактура без обект или разпределение“ (FLOW-033 L33) + аларма „фактура/ред без окончателно разпределение“ (FLOW-026 L21); показва се в „фактури за разпределяне“ с drill-down (FLOW-008 L90, L126).
4. Всяка промяна на разпределението = корекция в източника с AuditEvent; парични записи само Owner/Admin/Accountant (Р14/Р20).
5. Разпределената част влиза в P&L само по пътя от D-04 (Път А при изписване, Път Б при разпределения ред/приемане).
ЧАКА решение на Крум (не програмирай, остави конфигурируемо/дълг): собственик/срок/тежест на DQ issue; дали плащане е позволено при неразпределен остатък; дали разпределение към overhead иска Approval; къде се показва висящото (на обекта или само фирмено); толеранс при стойностни редове; ескалация при просрочие.
