## Какво да се направи
1. Канонично движение „сторно на получаване“ (receipt reversal) за складово получаване и за директна доставка към обект: обратно движение със същото количество/партида/цена, причина, връзка към оригинала; оригиналът остава. Само ако количеството още е налично (не е изписано/прехвърлено) — иначе 409 с обяснение какво първо трябва да се сторнира.
2. Сторното освобождава заключването на реда от фактура (покритото количество намалява атомарно в същата per-line lock транзакция), така че разпределението може да се коригира.
3. FIFO слоевете и стойностите се коригират точно; rebuild ×2 дава същото.
4. Права: по R16/R27/R28 (същите като за получаване + финансова роля за стойности); Idempotency-Key (Р29); canonical AuditEvent в транзакцията.
5. Без hard delete. Без промяна на правилата на #55.

## Тестове (real Mongo, 3 режима)
- получаване → сторно → разпределението се отключва → ново разпределение → нова доставка: разход точен live + rebuild ×2.
- сторно на вече изписано количество → 409.
- конкурентно сторно ∥ изписване ×10.
- повторение със същия ключ → един запис; crash след AuditEvent → един запис.
- Gates: R0, W0 същите 15, A2C/A1 0, PM-01 реален (0 skipped), warehouse suite.
