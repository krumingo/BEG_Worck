## 5. Работен цикъл за всяка задача (решение на Крум, 17.10.2026)

```text
1. Claude (оркестратор) прави план и задача         → docs/architecture/tasks/<ID>.md
2. Claude праща на Крум: „Задача <ID>: … Да?“        → телефон + табло
3. Крум: „да“
4. Claude пуска отделна Claude Code сесия            → клон + Draft PR
5. Code свършва и докладва на оркестратора
6. Claude проверява diff-а байтово (cmp/diff, тестове)
7. Claude праща на Крум: „<ID> готова, трябва Codex“ → готов текст за Codex (табло + PR коментар)
8. Крум копира текста и го дава на Codex
9. Codex публикува ревю в PR-а                       → Claude се събужда от GitHub събитието
10. Claude решава: PASS → предлага merge на Крум; CHANGES_REQUESTED → нова корекция
11. Claude праща на Крум какво предлага             → Крум „да“ → обратно към 4
```

**Тест на живо с бот (решение на Крум, 17.10.2026) — задължителен за всяка задача:**
- Code вдига локално копие на приложението: тестова MongoDB в Docker, backend и frontend build.
- Playwright бот минава сценария на задачата: положителен случай + забранен случай. Записват се скрийншоти (и видео, където има смисъл).
- Скрийншотите влизат в PR-а. Оркестраторът повтаря бот-теста сам и го приема само ако видяното съвпада.
- Само локално. Без staging и production, докато Крум не реши друго.

Правила:
- Без „да“ от Крум не тръгва нито една нова задача и нито една корекция.
- Само Крум мерджва и деплойва.
- Самоотчетът на Code не е доказателство. Claude проверява кода и тестовете сам, преди да поиска Codex.
- Таблото и хронологията се обновяват на всяка стъпка.
