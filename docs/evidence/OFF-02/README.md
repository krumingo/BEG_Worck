# OFF-02: offer write responses answer like the offer read (FG-350, R20)

Follow-up to OFF-01 (#79), approved by Krum. Branch `claude/off-02-offer-money-strip` from main `44e8d97`. FLOW Guard **FG-350**.

Canon: R20 (no client prices / margin for non-finance roles); FLOW-010; SEC-02 addendum A (D1: strip money, keep quantities and statuses).

## Problem (proved on main first)

`GET /offers/{id}` strips the client prices and totals for a caller without the finance right (SEC-02-A `strip_money_for_non_finance`). The offer **writes** a SiteManager may call returned the whole offer.

What a SiteManager got on main `44e8d97` (real Mongo rs0, off mode):

| Write | Money keys in the response |
|---|---|
| `POST /offers` | subtotal, vat_amount, total, line_total, material/labor_unit_cost, line_material/labor_cost |
| `PUT /offers/{id}/lines` | the same |
| `POST /offers/{id}/versions/{n}/restore` | the same |
| `POST /offers/{id}/new-version` | subtotal, vat_amount, total, line_total, material/labor_unit_cost |
| `POST /offers/import-confirm` | the same as POST /offers |
| `POST /offers/import-preview` | material_price, labor_price, total |
| `POST /extra-works/create-offer` | the same as POST /offers |
| `POST /projects/{id}/smr-to-offer` | subtotal |
| `POST /offers/{id}/versions` (snapshot) | none (already money-free) |

`backend/tests/test_off_02_offer_money_strip.py` on main's code: **9 failed, 3 passed**. The 3 that pass are the finance-roles regression check, which already held. Red commit: `9e9611f` (tests only); the final test file was re-checked on a worktree of `44e8d97`.

## Fix

`strip_money_for_non_finance` (SEC-02-A, unchanged) now also wraps these routes. Each one is registered in `app/permissions/finance_read.FINANCE_READS` as **R20-5M / `finance.money_values.read` / CANON_D1 + "OFF-02 FG-350"**, next to SEC-02-E's `PUT /offers/{id}` and `POST /offers/{id}/send`:

| Route | Module |
|---|---|
| `POST /offers` | offers.py |
| `PUT /offers/{offer_id}/lines` | offers.py |
| `POST /offers/{offer_id}/accept` | offers.py |
| `POST /offers/{offer_id}/reject` | offers.py |
| `POST /offers/{offer_id}/new-version` | offers.py |
| `POST /offers/{offer_id}/cancel` | offers.py |
| `POST /offers/import-preview` | offers.py |
| `POST /offers/import-confirm` | offers.py |
| `POST /offers/{offer_id}/versions` | offer_versions.py |
| `POST /offers/{offer_id}/versions/{version_number}/restore` | offer_versions.py |
| `POST /extra-works/create-offer` | extra_works.py |
| `POST /projects/{project_id}/smr-to-offer` | extra_works.py |

Accept, reject and cancel are Admin/Owner-only by role in off and shadow mode. In enforce the finance right comes from the Permission Service, not the role name, so their answers go through the same strip.

Already stripped before OFF-02: every offer GET, `PUT /offers/{id}`, `POST /offers/{id}/send`.

Not stripped, and why:
- `DELETE /offers/{id}` and `DELETE /offers/{id}/versions/{n}` answer `{ok}` only.
- The public review page and the client's respond are the CLIENT's view (R43: combined unit price only), not a staff role's.
- `missing-smr/*/to-offer`, `missing-smr/batch-to-offer` and `smr-analyses/{id}/to-offer` create an offer but answer ids and counts only.

**Who may write an offer is unchanged** (a separate question for Krum); only the response changes. Finance roles still get every money field.

## FLOW Guard FG-472 (R67 + R20) — the offer execution budget

- `PUT /offer-budgets/{offer_id}` let any M2 role write budget unit costs and margin %, with no AuditEvent.

**Red first:** `d3d6548` (tests only). `test_09` and `test_10` fail in 3 of 3 modes on `56913a4`.

**Fix `82312a2`:**
- **PUT:** `require_money_write("offers.offer_budget.update")` is the first dependency, so Owner/Admin/Accountant write and every other role gets 403 before any read or write. The budget rows and ONE canonical AuditEvent `offers.offer_budget.updated` (each line with its new cost / margin values) are written in one transaction. `offer_line_budgets` joins the collections created outside transactions.
- **GET:** `strip_money_for_non_finance`, plus an explicit non-finance view (`line_id, activity_name, unit, qty, planned_labor_hours, notes, has_budget`). The keys `sale_*` / `sale` are not money words for the generic strip, hence the allow-list. Finance roles see everything as before.

**Important:** this router is **not mounted** in `server.py`: no served route, no PM-01 cell, no frontend caller. FG-472 is therefore **not reachable in the running app today**; the module is hardened in case it is ever mounted.
- The action is in `OFFER_WRITE_ACTIONS` and is checked on the router itself (`test_08`, `UNMOUNTED_R67_ROUTES`), not in the served-route registries.
- Re-running the PM-01 and SEC-02 harnesses gives **no semantic change**: the matrix is byte-identical, and the SEC-02 results differ only in run-specific tenant ids, hashes and seconds, which are not committed.

## F-89-01 [P1] (Codex, PR #89) — the bearer review link in staff responses

**The leak:** `GET /offers/{id}` hid the prices from a SiteManager (SEC-02 strip) but kept `review_token`. With it he opened the public `GET /offers/review/{token}` (prices, against R20) and `POST /offers/review/{token}/respond` approve (Accepted, against R67).

**Every surface, enumerated twice:**
1. **By the code.** `review_token` / `review_url` are written only in `app/routes/offers.py`. The snapshots (`create_snapshot`, the send snapshot), `offer_events`, `audit_logs` and the AuditEvent diffs do not copy them. PDF and XLSX are finance-only, and their code never reads the token. Of the other modules that read `offers`, only `projects.py` (the project dashboard) projects `review_token` into a response: `extra_offers`.
2. **By a scan of the running app.** `backend/tools/off02_review_token_scan.py` covers every GET route of `server.app` (389). It calls each one as the five non-finance roles (SiteManager/requester, Technician, Warehousekeeper, Driver, Viewer) in off, shadow and enforce, 6984 calls, and searches the raw body (JSON, PDF, XLSX alike) for the two seeded tokens, the keys `review_token` / `review_url` and `/offers/review/`.
   - **Before the fix:** 3 leaking routes, in every mode — `/api/offers`, `/api/offers/{offer_id}`, and `/api/projects/{project_id}/dashboard` (the dashboard also leaks to a Warehousekeeper and a Driver). Evidence: `scan_review_link_before_fix.json`.
   - **After the fix:** **0 hits** (`scan_review_link.json`).
   - **Control:** the Owner still sees the link on the same 3 routes.

**Red first:** `28cbfa5` (tests only). `test_11` and `test_12` fail in 3 of 3 modes.

**Fix `007c2cc`:**
- `finance_read.strip_money` is the one strip every non-finance view goes through: `strip_money_for_non_finance` on the offer reads and writes, the versions, the events and the project dashboard. It now also removes `BEARER_LINK_KEYS = {review_token, review_url}`, at any depth, and `keep` never brings them back.
- **Not removed:** `review_token_version` and `review_token_status` / `revoked_*` stay. They are metadata (which version the link is bound to, whether it was revoked), not the link.
- **Finance:** keeps the link in the offer editor (GET) and in the send answer.
- **The public client flow:** unchanged.

**Tests (`test_off_02`), real rs0, off, shadow and enforce:**
- **`test_11`:** a SiteManager, Technician, Viewer and Driver get no token, key or `/offers/review/` from the single offer, the lists (all, by project, by status), the versions, version 1, the events or the project dashboard. The SiteManager's reads really answered 200, so the surfaces were exercised. The offer stays Sent. Owner and Admin still get the token. The client's public GET and approve still work, and the offer ends Accepted.
- **`test_12`:** the send answer gives the Accountant `review_url` and the token. With `money_values_visible` forced to False, it carries neither (defence in depth).

**Harness evidence:** re-running PM-01, SEC-01-C02 and SEC-02 gives **no semantic change**. The matrix is byte-identical; the other files differ only in seconds and run-specific tenant ids, which are not committed. The A1 and A2B inventories are unchanged.
