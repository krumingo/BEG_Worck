# FLOW-004 — Оферта → Акт → Остатък → Прогноза

> **Статус:** 100% — BUSINESS LOCK  
> **Последна проверка:** 20.07.2026  
> **Implementation Gate:** отделна техническа проверка по FLOW-042

## Цел

FLOW-004 определя как одобрена оферта се превръща в актуване, как се следят количества, суми, остатъци, аванси, ретенции и връзка към фактуриране.

## Основни слоеве

```text
Оферта / договорен обхват
→ изпълнение
→ измерване
→ акт
→ фактура
→ плащане
→ остатък
```

Актът доказва и признава извършена работа. Фактурата и плащането са във FLOW-006.

## Договор на крайна цена

При fixed-price договор актовете не могат да превишават договореното количество и единична цена по офертата.

Сборът на всички актове трябва да стигне до договореното количество и стойност, без да ги надвишава.

```text
остатък количество = офертно количество - актувано количество
остатък стойност = договорена стойност - актувана стойност
```

Предвидими съпътстващи разходи като вишка, скеле, достъп и логистика са риск на строителя при крайна цена, освен ако има ново възлагане/анекс.

## Договор на измерено количество

При remeasurement/unit-rate договор количеството не е константа. Плаща се реално измереното и одобрено количество по действащата единична цена.

```text
актова стойност = одобрено измерено количество × действаща единична цена
```

Офертното количество е прогноза, не твърд таван.

Промяна на единична цена става само чрез анекс. По подразбиране важи за работа след влизане в сила на анекса, освен ако анексът изрично казва друго.

## Аванси

При акт се показва:

```text
брутна стойност на акта
прихванат аванс
ретенция
други удръжки
нето за фактуриране / плащане
```

Прихващането на аванс не намалява извършеното количество или брутната стойност.

## Ретенции

Ретенцията е временно задържано вземане, не отстъпка и не разход.

Тя е конфигурируема по договор:

```text
процент или сума
база
условие за освобождаване
падеж
връзка с банкова гаранция
```

Освобождаването на ретенция минава през FLOW-006 / Payment ledger.

## Актове за допълнителни СМР

Допълнително СМР се актува само ако има договорно основание:

```text
допълнителна оферта
писмено клиентско одобрение
анекс, когато е необходим
одобрен Change Request
```

## Какво НЕ трябва да позволява този FLOW

- акт над договорения обхват при крайна цена;
- различна единична цена в акт без анекс;
- акт по допълнително СМР без договорно основание;
- фактура или плащане директно от акта без FLOW-006;
- ретенция да се третира като отстъпка;
- стар акт да се редактира тихо след одобрение;
- актуване на неодобрено измерване;
- едно и също количество да се актува два пъти.

## Какво трябва да вижда Крум

- договорено / изпълнено / актувано / фактурирано / платено;
- остатък по всеки СМР ред;
- актове по договорна база;
- аванс, прихванат аванс и оставащ аванс;
- ретенции по акт и по договор;
- опити за надвишаване на количество/стойност;
- прогнозна стойност при измерено количество;
- чакащи актове и актове за корекция.

## Минимална проверка преди Implementation Gate

- два actuation режима: fixed_price и remeasurement;
- актови редове с връзка към offer_line / contract_basis / work_package;
- контрол за остатък;
- ретенция и аванс като отделни финансови слоеве;
- корекция/реверс вместо тихо редактиране;
- тестове за надвишаване, частично актуване, анекс и ретенция.
