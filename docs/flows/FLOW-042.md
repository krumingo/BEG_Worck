## Цел

FLOW-042 превръща всяко заключено бизнес правило в проверим тест и определя кога дадена промяна е действително готова за приемане. FLOW-017 описва работния процес с GitHub/Claude/ChatGPT/Emergent; FLOW-042 описва тестовете, доказателствата и приемането.

## Основен процес

```text
Business Lock
→ техническа спецификация
→ код / branch / commit / PR
→ автоматични тестове
→ ръчен тест по сценарий
→ доказателства
→ приемане от Крум
→ release
```

## Минимален тестов пакет за всеки FLOW

- разрешен сценарий;
- забранен сценарий;
- права и опит за заобикаляне;
- корекция / реверс;
- audit история;
- Data Quality / блокировка;
- екранът и справката, които вижда Крум;
- повторно изпращане / idempotency, когато е приложимо;
- offline/sync, когато е приложимо.

## Статуси

- Чернова;
- Готов за изпълнение;
- В тест;
- Неуспешен;
- Върнат за корекция;
- Успешен технически;
- Чака Крум;
- Приет;
- Отказан;
- Регресия.

## Какво трябва да вижда Крум

- кои FLOW-ове имат Business Lock;
- кои имат техническа спецификация;
- кои са в разработка;
- кои тестове са успешни/неуспешни;
- точно какво да провери сам;
- снимка, видео, лог или друг доказателствен файл;
- свързания GitHub branch, commit и PR;
- нерешени дефекти и блокиращи регресии;
- коя версия е в production и коя е в standby.

## Какво НЕ трябва да позволява

- „100% FLOW“ да се приема автоматично за готов код;
- release без тест на забранения сценарий;
- приемане без връзка към конкретна версия/commit;
- успешно състояние без доказателство;
- Emergent/AI да затвори окончателно тест вместо Крум;
- неуспешен критичен тест да бъде скрит от общия статус;
- нов release да няма план за rollback.
